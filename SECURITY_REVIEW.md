# Security review scope

The Go rewrite review covers bounded parsers, strict schemas, group ticket safety, conservative reuse, cumulative budgets, durable metadata privacy, outbox lifecycle, loopback inspection, exact pod selection, dashboard origin checks, cancellation and private atomic reporting.

Tests do not contact clusters/providers or load workstation credentials. Integration coverage uses fake client-go clients, synthetic SQLite state in-memory transports, local HTTP provider fakes and a real SPDY upgrade/port-forward exchange against a fake Kubernetes API. Socket binding and image builds may be restricted by the execution environment; actual results are recorded in [VALIDATION.md](VALIDATION.md).

The pinned modernc Unix VFS `xShmMap` bypasses `xOpen` and directly opens/truncates SHM. Direct state startup now validates existing SHM relative to the private directory descriptor, with no-follow/nonblocking operations and current-owner/private-mode/single-link/regular-file checks before SQLite initialization. Real-WAL regressions reproduced external-hardlink modification and read-only FIFO blocking before the fix; recovery tests preserve committed rows across volume preparation. WAL and rollback journals use the existing verified `xOpen`. No alternate locking or recovery implementation is introduced. Root/same-identity name replacement after validation remains outside the boundary, including absent-name creation and SHM replacement before SQLite's eventual open; see [controller state opening](docs/controller.md).

Residual limitations include best-effort redaction, local-machine access to loopback services, operator-supplied kubeconfig plugins, at-least-once delivery, process-local live cursors, conservative polling gaps, provider token-accounting assumptions. Native Go UI workflows retain browser, HTTP and terminal security regression tests. [Migration](docs/migration.md) lists behavior changes rather than silently claiming equivalent protection or functionality.
