# Durable controller

```sh
jevernetes controller --namespace demo --state /var/lib/jevernetes/state.db \
  --offline --sink stdout --inspect-port 9091 --selector app=api
```

Controller mode uses in-cluster configuration and requires namespace/state. It continuously collects read-only logs, evaluates deterministic policy, and atomically records novelty, incident counters and notification intent in SQLite. It cannot execute model actions or modify workloads. `--policy` accepts a strict JSON object; omitted fields use defaults. Unknown fields and invalid ranges fail before credentials or collection.

Default policy reviews uncertain, truncated, sensitive, failed or insufficient-confidence events. An important judgment with all three confidences at least 0.85 notifies when its category is security/fraud or severity is degraded/impact/outage. Cooldown is 300 seconds; recurrence window 900 seconds, escalation every five occurrences, capped at eight levels. A transition from review to notify can bypass cooldown. Policy notifications are advisory. Offline mode still generates review notifications.

The database uses one writer, an OS lock, rollback journal, FULL synchronization, secure deletion, 4 KiB pages and a 256 MiB page limit. Tables are capped at 10,000 rows. At capacity, indexed oldest-first eviction removes seen entries by observation time, incidents by last touch, verdicts by expiry, and terminal outbox entries by update time; opaque keys break ties. Pending outbox entries are never eviction candidates. Transactional counters avoid per-event table counts. Schemas 1/2/3 migrate to schema 4 transactionally; [migration details](migration.md) explain cache invalidation and metadata-only notification schema 2. No message bodies, readable source labels, template samples or keys enter new persistent rows. Notification payloads contain only opaque IDs, enums, confidences and counters.

`--sink stdout` prints JSON notifications. It conflicts with controller `--json`, avoiding mixed stdout protocols. `--sink webhook` reads `JEV_WEBHOOK_URL` or `JEV_WEBHOOK_URL_FILE`, requires HTTPS without userinfo/fragments, rejects redirects, caps response consumption and sends `Idempotency-Key`. Delivery is at least once: attempts are recorded before sending, retries use bounded backoff, and eight failed attempts mark an item dead. A consumer should deduplicate by `notification_id`. No webhook is contacted by offline tests.

`--listen` defaults to `0.0.0.0:9090` for `/livez`, `/readyz` and Prometheus `/metrics`. `/readyz` is 503 once collection stops. `--inspect-port 9091` enables a separate loopback-only listener. Do not expose it through a Service or Ingress.

`--duration`, explicit event/stream/queue caps and provider budgets bound collection/analysis. Controller mode defaults to `--max-events 0` (unbounded lifetime ingestion); file and standalone Kubernetes commands retain their 100,000-event default. Memory, disk, queues and stream concurrency remain bounded. With inspection or `--hold-after-stop`, a normal bounded stop retains delivery and inspection until SIGINT/SIGTERM; it does not reset budgets or restart collection. Fatal store/service errors cancel the controller. Shutdown joins collection/delivery/server workers and writes the final report when requested. A report-write failure is fatal and never reported as success.

Provision a current-user-owned local state directory with mode 0700; existing public directories and directory symlinks are rejected without changing their permissions. SQLite on network filesystems is not supported. `--rescore` bypasses durable verdict lookup; safe verdicts otherwise obey exact evidence hashes, contract identity and TTL. Controller inspection is sampled rather than a cross-component transaction.

When all 10,000 outbox slots are pending, the current event transaction rolls back and ingestion retries it while the delivery worker continues. Live producers can then drop at the bounded queue; `outbox_backpressure`, `coverage_outbox_backpressure`, `dropped` and `coverage_queue_drop` expose this condition. Shutdown can leave the in-memory event unapplied, with incomplete coverage; already committed delivery intent remains durable. Delivery remains at least once, with one due attempt per second and a maximum of eight attempts per notification. Provision sink throughput accordingly.

`state_seen_evicted`, `state_incidents_evicted`, `state_verdicts_evicted` and `state_outbox_evicted` are durable cumulative counters exposed through inspection, reports and Prometheus. Eviction shortens novelty/incident history, can cause repeated reviews/notifications, and prevents a complete-coverage claim. Entries need not survive seven days under capacity pressure; under low volume they can remain until displaced. Verdict lookup still enforces expiry and rollback-clock checks. Notification IDs use a durable global sequence in a new identity namespace, so incident eviction cannot reuse delivery identities. Existing queued IDs remain unchanged.

State and lock files are opened with Unix no-follow semantics, then checked through their descriptors for regular-file type, current ownership, private mode and a single link. The state directory is retained through a descriptor; its canonical ancestry must be owned by root/current user and exclude other-user renames (non-writable directories or sticky-directory protection). The leaf directory cannot be a symlink. Every VFS open rechecks its directory identity and rejects existing special files, symlinks, public files and extra links before delegating to SQLite, preventing a pre-existing FIFO journal from blocking a read-only open. SQLite's actual descriptor is then checked; the main database must match the retained verified file.

The pinned modernc Unix VFS opens shared memory through `xShmMap`, bypassing `xOpen`. Before any SQLite initialization, direct `controller --state` startup checks an existing `-shm` leaf relative to the retained directory descriptor: no-follow metadata rejects special files, then a no-follow, nonblocking read-only open verifies regular-file type, current ownership, private mode and a single link through the descriptor. Unsafe SHM fails without repair, truncation or unlinking. An absent SHM is left absent; SQLite creates it with the verified database's private mode only when WAL recovery needs it. Proactive creation would leave misleading unused sidecars on normal DELETE-journal databases without preventing same-identity replacement. WAL and rollback-journal opens already pass through the verified VFS `xOpen`; they require no separate bypass fix.

The wrapper preserves the default VFS locking, WAL/rollback recovery and synchronization. Tests exercise real WAL and hot-journal recovery after abrupt process exit, committed-row preservation through volume preparation, and the writer lock. URI characters are escaped, and all connection-local PRAGMAs are applied to replacement connections after interruption.

The adapter depends on the pinned modernc Unix ABI and must be revalidated on dependency upgrades. It is not a boundary against root or another process with the same OS identity. Such a process can rename the directory or create/swap a sidecar between validation and SQLite's later path-based Unix open, including the direct SHM open in `xShmMap`; a hardlink inserted in that interval can be modified/truncated and a FIFO can still block. The SHM preflight does not retain or verify SQLite's eventual SHM descriptor, and an absence check does not reserve the name. The portable wrapper cannot make that path-based open atomic with the check. Main-file descriptor matching detects regular-file replacement before database reads; it does not eliminate same-user sidecar or rename races. Use a private local filesystem directory controlled exclusively by the controller's OS identity.

Each snapshot and reconnect performs a fresh pod GET and checks UID, container kind/name, runtime container ID and restart count before log GET. Confirmed replacement/removal retires a stream. Transient GET errors or temporarily missing validation data retry with a context-aware exponential delay from 100 ms to a five-second cap, retaining the parser and replay cursor and emitting `identity_unavailable`; logs never open without successful validation. An instance discovered without a runtime ID cannot be validated and is retired. Previous-container attribution uses restart count minus one. Kubernetes log GET has no UID/container-instance precondition, so replacement between validation and log GET cannot be eliminated. Discovery polls every five seconds and all live history remains incomplete. Transport replay tracking is process-local: at most 4,096 raw physical-line digests with multiplicity at the latest transport timestamp. It hashes discarded oversized bytes too, never redacted event text. The wire `sinceTime` is whole-second precision. During reconnect replay, earlier lines within that requested second are skipped and equal latest-timestamp multiplicities are consumed; replay ends when those saved multiplicities are exhausted or a newer timestamp arrives. Subsequently, out-of-order lines are retained with a coverage gap. Cursor overflow, untimestamped/partial lines and every reconnect (including EOF) also produce coverage indicators. Unterminated Kubernetes physical lines mark their events truncated and parse-uncertain, including continuation appends; clean file EOF retains normal semantics. Consumer errors, including EOF-shaped errors, terminate collection without reconnecting. Unprovable replay is retained rather than silently suppressed.

The Kubernetes template provisions this directory with a non-root, same-image `prepare-state-volume` init command. Keep `fsGroup: 65532` for initial PVC access, but mount only its mode-0700 `private` child into the controller through `subPath: private`; mounting the volume root directly is incompatible with the private-directory checks. The init command repairs modes after each pod's volume processing, preserves known legacy SQLite artifacts through synced staging, and rejects conflicting or interrupted layouts. Use one replica with `Recreate` and an exclusively used local volume. Back up the entire volume before upgrade; see [deployment migration and recovery](../deploy/README.md#private-state-volume-and-legacy-upgrades) for exact artifacts, image replacement, security settings and manual recovery requirements. The init command changes provisioning only; normal `controller` state opening still rejects unsafe modes without repairing them.
