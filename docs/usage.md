# CLI usage

```sh
jevernetes-go files examples/mixed.log --offline --json
jevernetes-go files application.txt.gz - --offline --output report.json
jevernetes-go k8s --namespace demo --selector app=api --offline --since 30m
jevernetes-go k8s -f --namespace demo --offline --tail 0 --duration 60
jevernetes-go dashboard --report report.json
```

`kubernetes` aliases `k8s`; `--live` aliases `--follow`/`-f`. The Go release supplies the `jev-go` executable alias; existing Rust command names remain available. `--help` is the authoritative flag list. Unknown options and unsupported compatibility options fail before inputs or credentials are opened.

Files support plain text, JSONL, stack-trace continuations, gzip including concatenated members, and `-` once for stdin. Missing files produce coverage gaps while subsequent inputs continue. `--max-file-bytes` limits decompressed input (default 32 MiB). Lines are bounded at 65,536 bytes and events at 16,000 UTF-8 bytes. Incomplete byte-limit fragments and oversized lines/events are marked truncated. Unterminated Kubernetes physical lines also mark the containing event truncated and parse-uncertain; normal file EOF does not. Secret-like fields, authorization strings, URL credentials and private-key blocks are redacted before event storage. Duplicate JSON keys retain their conflicting, safely redacted values within the evidence bounds and mark the event parse-uncertain, excluding grouping/durable reuse and requiring conservative policy handling (review by default). Interrupted finalization marks any pending event incomplete, even after a newline-terminated header. Redaction is best effort; reports remain sensitive.

`--max-events` is global (default 100,000 for files/standalone Kubernetes; controller defaults to 0 for unbounded lifetime ingestion); `--retain-events` bounds retained report events (default 2,000 for every mode). Event totals remain cumulative. A positive event cap stops collection immediately after exactly that many successful queue admissions and drains admitted analysis; no extra event or EOF is required. Live queue drops do not consume the admission cap. Reaching a bound or evicting retained events makes coverage partial. Live collection uses `--max-streams` (64), `--queue-size` (1,024), five-second pod polling and context-aware reconnects. Snapshot discovery is capped at 4,096 pods, with 200-pod pages and a 15-second request bound. Regular, init, ephemeral and previous container instances are included where status records permit; `--no-previous` excludes previous logs. Snapshot log requests have a 30-second bound. `--since` accepts integer seconds or s/m/h/d, default 1h; `--tail` defaults to 500. `--context` conflicts with `--in-cluster`.

Offline mode uses keyword/HTTP-5xx rules, never AI confidence or provider credentials. Online mode defaults to TypeSafe; `--risk-provider openai|anthropic` requires explicit `--model`, `--input-price` and `--output-price`. Prices are operator inputs, not verified billing rates. Keys use the selected `*_API_KEY` or `*_API_KEY_FILE`; TypeSafe also accepts `TYPESAFEAI_API_KEY`. Key files must be regular and at most 16 KiB. Never put keys in command arguments.

`--batch-size` is 1–64, default 8; fill deadline 350ms. `--max-batches` defaults to 500. `--drain-max-provider-attempts` caps all attempts, including retries. `--max-cost` defaults to $0.25 in cumulative conservative reservations; input tokens are bounded by serialized request bytes and output by the requested maximum. Missing usage or a reservation underestimate opens the breaker. Reservations are not refunded. Billing guarantees depend on provider adherence to token limits and configured prices; TypeSafe does not provide the same output-token cap. Error bodies and transport diagnostics are never printed.

Use exact grouping by default; `--no-grouping`/`--grouping-strategy off` disables reuse. [Drain grouping](drain-template-mining.md), [adaptive audits](adaptive-log-learning.md), and [template learning](provider-template-learning.md) are opt-in. Unsupported fixed-sampling and uncertain-cache compatibility flags fail explicitly.

SIGINT/SIGTERM cancels collection and provider requests, drains queued events conservatively, joins workers and attempts a final report. Blocking stdin is closed on cancellation. `--json` reserves stdout for JSON; progress and errors use stderr. Reports use schema 2 with `runtime: "go"`, `summary`, `events`, `coverage`, `important_groups`, `usage`, `provider_usage`, `metrics` and learning sections. `--output` uses a 0600 temporary file, sync and atomic rename; newly created directories use 0700. Plain evidence, controller stdout notifications, remote samples and startup diagnostics use synchronous context-bound descriptor writes and propagate output errors. Final JSON/plain reports and terminal error diagnostics have a one-second independent grace window, allowing a signal's final report to reach a draining consumer while bounding shutdown if a pipe stops draining. The private `--output` report is attempted before final stdout. Interrupted stdout can be partial; a valid complete JSON document is only guaranteed after successful delivery. No background write goroutine is left behind. File-descriptor output has one in-process owner, with temporary nonblocking flags serialized and restored; embedding callers supplying arbitrary `io.Writer` implementations must keep them synchronous/nonblocking or provide their own cancellation. Regular-file storage operations still depend on the local filesystem completing I/O.

Exit codes: 0 complete within the requested file window; 1 configuration/runtime failure; 2 partial coverage or CLI option parsing failure; 130 interruption. Important events alone do not change the code. Every Kubernetes report is partial. No exactly-once or complete-history claim is made.

The Go dashboard opens schema-1/schema-2 reports and version-1 human review rules directly. Run `dashboard --reports-dir .runs` (default), optionally `--report saved.json`; `--listen` defaults to `127.0.0.1:8765`, and `--port` is a compatibility alias. The established UI supports upload scans, live Kubernetes collection, source/importance/confidence filters, grouped occurrences, reversible bulk acknowledgements, expected rules, surrounding context, prompt/JSON export and themes. All collection, search, context and review APIs run in Go. The compact controller view remains at `/controller/` and as `--inspection-only`.

Use `files PATH --tui` or `k8s -f --tui` for the native terminal. Keys: 1–5 or Tab/Shift+Tab select Important/Routine/Needs Review/All/Search; arrows/j/k and PageUp/PageDown navigate; Enter opens full evidence; Esc returns; g toggles grouping; i shows occurrence IDs/timestamps; q quits. Open details and search results retain their original evidence when live events are evicted. Terminal control bytes in logs cannot execute terminal commands. `--tui` conflicts with JSON and log stdin. Quit and signals join collection/search workers, restore the terminal and save the requested report.

Press `/` (or `?`) for semantic search or `f` for exact text. While editing, Tab switches mode, Ctrl+B cycles 4/16/64 batches, Ctrl+U clears, arrows/Home/End move the cursor, and Backspace/Delete edit Unicode text. Search freezes the current retained window, includes pending evidence, groups exact occurrences, and caches successful decisions for five minutes with occurrence-aware keys. Its TypeSafe requests and $0.01 cost bound are separate from collection. Press x to stop a search while retaining completed results. Offline mode supports exact search without credentials or provider requests.

Human expected-event rules use `--rules-file` (default `.runs/.review-rules.json` for files/k8s). They are literal and reversible, never model-template rules. Expected events skip provider dispatch; disabling the rule restores the original judgment, or explicit unknown when analysis was skipped. Dashboard reviews persist beside reports. Use one dashboard writer per review directory; do not run separate Python/Go writers against the same file concurrently.

Compatibility controls include `--workers 1..16`, `--collect-workers 1..32`, `--discovery-interval 1..3600`, `-n`, `-l`, `-A`/`--all-namespaces`, and `--top`. Go defaults to one provider worker and one snapshot worker, five-second discovery, and no additional final top-group listing. Parallel provider requests share the same cumulative budgets and preserve result order. Snapshot workers share global admission limits. `--top N` appends N important groups to the plain summary.

Go framing preserves delayed multiline continuations: a quiet singleton is displayed as pending and is finalized by the next header or stream end. This intentionally differs from the retained runtimes' quiet flush. Kubernetes coverage, retention/byte limits, event identities, runtime defaults and output layout are not byte-identical between runtimes. No exactly-once or complete-history guarantee is added. Intake caps/duration drain admitted work, and controller budget exhaustion exits for supervised restart.
