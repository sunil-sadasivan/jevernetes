# Moving to the Go implementation

Go now replaces the Python and Rust implementations. The CLI, TUI, investigation dashboard and controller share one native executable, named `jevernetes`; `jev` is its release alias. There is no Python package or Cargo build in the source tree, and neither language runtime is needed to run the product.

```sh
go build -o ./jevernetes ./cmd/jevernetes
./jevernetes files examples/mixed.log --offline --tui
./jevernetes dashboard --reports-dir .runs
```

Use `./jevernetes` to select the newly built executable explicitly. An older installation elsewhere on `PATH` is not changed by this build. Release archives contain `jevernetes` and `jev`; update scripts that used the transitional Go-suffixed binary names. See [usage](usage.md) for flags and UI controls.

## Existing reports and reviews

Select the existing private reports directory with `--reports-dir`. The native investigation dashboard reads schema-1 and schema-2 reports and reads/writes version-1 `.review-rules.json` directly. No Python migration command or format conversion is required. Keep report filenames unchanged: schema-1 acknowledgement keys identify those filenames. Existing rule IDs, literal scopes, enabled/disabled states and acknowledgement event IDs remain meaningful; disabling expected rules restores original judgments. Human expected-event rules remain separate from model-reviewed provider-template rules.

Before changing installations, stop writers and preserve a private backup of reports, review rules and controller state. If copying a reports directory, include its hidden `.review-rules.json` and keep its filenames and permissions. Do not run old and new writers concurrently. The native APIs reject unsafe paths and bound reads and writes; they do not silently repair or downgrade input files.

The compact inspector at `/controller/` (or `--inspection-only`) also reads schema-1/2 reports, with a 64 MiB / 100,000-event import bound. It offers literal, case-insensitive paged search. Oversized events and missing coverage are marked explicitly; retain the original report for full evidence. Imported reports without an explicit schema-2 completeness assertion remain unverified.

## Acceptance and intentional differences

`python3 tools/check_parity.py --run` runs the native acceptance inventory: CLI ingestion, terminal/search, dashboard/context/reviews, report compatibility, providers, Kubernetes transport, controller/state/outbox, packaging and RBAC. `tools/check.sh` additionally runs race detection, vet, cross-builds, real executable HTTP/PTY checks and retirement checks. All six browser acceptance suites target Go's embedded assets. Python and Node are development test tools only.

Workflow equivalence does not mean byte-identical output. Go conservatively finishes multiline live events at the next header or stream end, rather than a quiet timer. Event IDs, defaults and output layout can differ; [usage](usage.md) documents the differences. Existing imported event IDs are preserved. Provider judgments, billing, production clusters, actual container-engine execution and a long production soak remain unverified by synthetic tests. Provider budgets are process bounds and can be renewed by a supervisor restart.

## Local Kubernetes credential helpers

Go collection and remote/dashboard inspection use a context-aware exec-credential transport for local kubeconfigs. Helpers receive the request's cancellation and the owning command's shutdown, with a separate 30-second execution ceiling. The process group is killed on cancellation and the command/output readers are joined; inspection HTTP shutdown also joins handlers. This applies to first authentication, expiry refresh, 401 refresh and SPDY upgrades. An HTTP timeout alone does not provide this guarantee. Helpers remain trusted local executable code, not a sandbox; deliberately detached processes outside their process group are outside this contract.

The transport accepts `client.authentication.k8s.io/v1` and `v1beta1`, preserves configured environment overrides, interactive modes, plugin allow/deny policy, explicit credential precedence, cluster information and per-cluster extension/audience data. Exec credential caches are per client, with no cross-client/global exec credential reuse. Tokens remain opaque; the API server validates their audience. Certificate/key pairs are parsed together, certificate rotation closes tracked HTTP connections, and TLS callbacks only use already-acquired credentials. 401 refresh prepares the next request without replaying the current one. Unknown or duplicate JSON fields, wrong kind/version, empty credentials, malformed pairs, expired credentials, control characters in tokens and output over 1 MiB fail closed. Noninteractive helper stderr and detailed parsing/command failures are suppressed. The native TUI suspends raw mode, mouse capture and its alternate screen for interactive authentication; its render/input loop shares the helper terminal lease and resumes only after the helper joins. Interactive helpers keep terminal prompts, foreground ownership and saved terminal attributes are restored after the helper joins on success, error, timeout or cancellation, and Ctrl-C returns cancellation. PTY regression coverage requires Python 3, already a repository development prerequisite.

SPDY cancellation closes the actual upgrade socket during request writes, proxy CONNECT/SOCKS negotiation, TLS handshakes, response headers and error-body reads. The socket callback is stopped and joined on failure or transfer to the established tunnel, and tunnel shutdown joins its lifecycle watcher. Configured dial hooks, proxy authentication, verified TLS, exec credentials and client-go HTTP/SPDY negotiation remain active. Custom dial/proxy callbacks remain trusted code and must honor their contexts.

Local kubeconfig/CA/certificate/key/token paths retain the strict regular-file contract. The fixed explicit in-cluster service-account credentials remain client-go owned. The controller's deployment-only projection opt-in is documented in [deployment operations](../deploy/README.md); it does not apply to local kubeconfigs.


Go HTTP and SPDY transports handle `auth-provider: oidc` through the same request-bound boundary. An unexpired cached `id-token` (with client-go's ten-second expiry margin) needs no discovery, refresh, or write. The API server remains responsible for token validation. Unsupported providers and mixed exec/auth-provider configurations fail initialization. Discovery and refresh inherit request and command cancellation, with a fifteen-second total ceiling and five-second dial, TLS and response-header limits. Responses are limited to 1 MiB; redirects and HTTPS-to-HTTP token-endpoint downgrades are rejected. Embedded issuer CA data and regular no-alias CA files are supported; relative issuer CA paths resolve against the kubeconfig directory. Issuer HTTP URLs remain compatible with existing local configurations. There is no process-wide OIDC token cache or context-free upstream refresh.

Refreshing requires one unambiguous kubeconfig loading path. Multiple-file OIDC configurations fail initialization; programmatically supplied configs without a verified destination support cached tokens only. The destination must be a current-user-owned, writable, private regular file with one link inside a private owned directory. Leaf/parent symlinks, FIFOs and other unsafe destinations fail before issuer contact. A bounded wait acquires client-go's `<kubeconfig>.lock` convention, then rereads the selected user's credentials before refreshing; separate Go clients therefore share persisted rotations without consuming the old refresh token twice. After a successful response, the latest file is reread, unrelated configuration edits are preserved, and only that user's OIDC tokens change. Changed provider settings or credentials fail closed. A private temporary file is synced, atomically renamed relative to the retained directory descriptor, and the directory is synced before the new token is used. Standard kubeconfig serialization preserves configuration fields and extensions, but rewrites formatting/comments. Other Kubernetes clients can read the resulting standard OIDC fields.

This transaction assumes a local filesystem and cooperating writers using the kubeconfig lock. Noncooperating edits visible at the final reread are rejected; arbitrary same-user/root replacement in the final check/rename interval is outside the ownership boundary. Other clients can read refreshed credentials, but must not refresh concurrently unless they honor the same lock. An interrupted exchange after an issuer consumes a rotating token, a malformed issuer response, or a storage failure can still require reauthentication; no client can atomically commit both issuer state and a local file. Network failures never trigger an automatic refresh replay. Discovery authentication-method metadata selects `client_secret_basic` (preferred when both are advertised) or `client_secret_post` before sending a refresh; an advertised list without either supported method fails before token dispatch. When metadata is omitted, Basic authentication is tried first and a single form-body fallback is allowed only after HTTP 401 or HTTP 400 with a complete JSON `invalid_client` response. Other HTTP errors, malformed/truncated responses and network failures do not trigger the probe. Empty client secrets are omitted from form-body authentication, matching the pinned OAuth library. Stale lock files are not removed automatically.

SPDY upgrade URLs use client-go's resolved server URL, including scheme-less host/port values, TLS defaults and explicit URL path prefixes. SPDY target TLS derives ServerName from the resolved API hostname even with verification disabled. An explicit `tls-server-name` remains authoritative; IP literals use Go's normal no-SNI behavior. Target inference does not overwrite HTTPS proxy TLS identity. Regression tests use real local TLS over in-memory connections for direct, HTTP/HTTPS CONNECT and SOCKS5 paths, plus verified TLS, custom dialing and cancellation. No external proxy or cluster is required.

Help, command help, usage and version rendering use the same cancellable descriptor ownership as command output. A full undrained stdout/stderr pipe exits on command cancellation; failed or short writes return exit 1, and cancellation returns 130. Cobra's existing successful text and exit codes are preserved. Application output retains its own context, including the independent final-report grace window. Custom library writers remain synchronous trusted code and must own their own blocking behavior.
