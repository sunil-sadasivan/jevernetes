# Compatibility and intentional differences

This Go release replaces the product backend with a native executable. It preserves the primary `files`, `k8s`/`kubernetes`, `controller`, `remote`, `dashboard` and `jev` entry points, but does not claim complete parity with the entire prior command surface.

| Contract | Go behavior / incompatibility |
| --- | --- |
| Reports | Schema 2, familiar event/judgment fields; `runtime` becomes `go`. Event/group hashes change. Retention defaults to 2,000 for files as well as live mode. Metrics contain implemented counters rather than the entire previous metric inventory. Historical projection fields are not fabricated. |
| Offline analysis | Rules retain important/uncertain behavior without provider confidence. Offline mode performs no template learning/reuse and reads no provider keys. |
| Exact reuse | More conservative: sensitive, multiline, security-shaped or oversized evidence cannot seed reuse; uncertain, unknown, low-confidence and security/fraud verdicts cannot be reused. |
| Drain | Strict IDs or classic numeric/IP/clock grammar. Protected numeric telemetry (including count, amount, bytes) stays literal. Positional codes stay literal. Path-shape and logger-prefix canonicalization are not implemented. These choices reduce reuse. |
| Group risk | One bounded dossier per exact eligible ticket at microbatch close; singleton analysis has no warmup count. Unsafe/failed group answers do not fan out reusable verdicts; unresolved siblings remain unknown. |
| Adaptive scheduling | Deterministic 32-to-configured-gap audits and TTL; no probabilistic drift sampler, feedback learner, burst-priority queue, normality probability model or automatic checkpoint restoration. Checkpoints are opaque diagnostic counters only. |
| Paid scheduling | Every online request uses cumulative reservations, attempt and batch caps. Missing accounting stops admission. There is no shared risk/template budget pool; templates have a separate explicit cap. Monetary caps are estimates, not billing guarantees. |
| Compatibility flags | `--drain-sample-rate`, `--drain-uncertain-ttl`, `--drain-max-cost` fail with an unsupported message. `--drain-budgeted` requires adaptive mode; it selects the same conservative scheduler used by all online requests. |
| Reviewed artifacts | Artifact version 2/schema 1 accepted with exact JSON shape, required/protected literals and string normalization. Logger-clock prefix grammars are rejected at load time. Reviewed rules can activate reuse in semantic mode; provider proposals alone cannot. |
| Provider learning | OpenAI/Anthropic shadow proposals and classic escalation reviews work with independent budgets. Automatic free-text masking is deliberately withheld: provider suggestions require a separately reviewed artifact. Two reviews maximum per batch, bounded samples/candidates/history. |
| SQLite | New schema 4; automatic transactional migration from schemas 1/2/3 retains incident/outbox IDs, status and attempts, converts notifications to metadata-only schema 2, invalidates schema-1/2 verdict caches, and adds transactional capacity counters. New notification IDs use a separate identity namespace and global sequence; existing delivery IDs are preserved. Secure deletion removes discarded evidence from active database pages; it cannot erase filesystem snapshots or backups. Future/unversioned foreign schemas fail closed. |
| Notifications | Schema 2 omits readable source/log evidence, adds hashed source/event identities, retains notification/incident IDs, judgment, decision, recurrence and observation time. Consumers must update for this privacy change. No webhook authentication-header configuration is provided; HTTPS URL configuration is supported. |
| Collection | Pod polling every five seconds replaces watch-based discovery. Live cursor state is process-local; duplicates and gaps remain possible after restart, rotation or cursor capacity. Initial/ephemeral instances require status records. |
| Remote inspection | Schema-1 status/detail, exact single-pod selection, fresh client-go SPDY forward per sample. A temporary loopback TCP listener is used. Metrics validation currently accepts the Go counter subset; older richer metric payloads may be rejected. |
| Dashboard | Native read-only report viewer and fixed-controller monitor. No browser-selected paths/targets/providers. Prior scan/live-tail/review-write/search/context/TUI backends are not provided. CLI `search`, `context`, `review`, `reviews`, `tui` and old write routes fail explicitly. `--controller-binary` fails because no subprocess bridge is used. |
| Static assets | Existing historical HTML/JS/media and helper tests remain as reference assets; the active UI is embedded from `internal/dashboard/web`. Historical demos do not imply current backend support. |
| Packaging | Native binary/source archives and multi-stage Go container. No interpreter runtime package, wheel or companion process. Linux/macOS only; file locking is Unix-specific. |

Old command options not listed in `--help` are rejected. Do not infer support from historical screenshots. Existing state files must be private regular files (0600); state directories must be current-user-owned, non-symlink directories with mode 0700 and protected canonical ancestry. Back up state before changing schemas; rollback to a prior executable cannot read schema 4.

Pristine migration tests use historical creation DDL from commits `41e4a58` (schema 1), `b9eeb6c` (schema 2), and `a3d42e0` (schema 3), stored as independent SQL fixtures. They start without schema-4 counters, triggers or eviction indexes, then verify row counts, transactional triggers, global-sequence advancement, schema-specific verdict invalidation, metadata conversion, and legacy queued-notification detail/delivery identities. Schema 1's unknown last decision remains nullable and conservative. Interrupted and deliberately replaced SQLite connections are tested for successful subsequent transactions and restoration of every configured PRAGMA.
